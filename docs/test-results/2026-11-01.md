## Findings
- Session names: the person renamed a desktop-app session to "session #3", but interccom kept calling it `test-545176` (the desktop app's random worktree folder name) and read that out. The hooks-module API (2.1.316) has no session title and no rename event: `$.session` has `id`, `cwd`, `repo`, …, and only the shell-hook `SessionStart` input carries `session_title`, once, at start. For now the person has to run `/interccom name <name>` as well. Desktop worktree sessions get unspeakable default names.

- Not knowing when you're heard: in wake mode the status line said `mic: listening` all the time. Built in 2bf4eea: chimes on "Hey Claude" (rising) and on delivery (falling), and a status line that says `listening to you…`, `sent to <name>` or `talking, can't hear you`. `/rename <name>` now renames the session for interccom too. Then, at the person's request, the status line became one plain word (68674be): Talking, Listening, Processing, Waiting, Not connected, Mic off.
  - ✅ Chimes: heard and approved.
  - ✅ `/rename`: a new session renamed "Test#4" took the name.
  - ✅ Statuses: after a restart they change at the right moments.
  - ✅ Title after a restart (1b16238): the session follows its title's first three words. After a restart, "Test #6" spoke as `test-6`.
  - ✅ Local engines in a real session: the person talked to a session running Kokoro + Speaches and found it "works quite nice".

- Flaky on Windows, fixed: "connect.mjs ends quietly with exit 0 when the event stream breaks after linking" saw exit code 3221226505 (0xC0000409) in 5 of 25 runs: Node aborted in process.exit while the broken stream was still closing. connect.mjs now ends on its own after a normal end; then 40 of 40 runs passed.

- Other audio on the speakers is heard as the person: a demo video with "Hey Claude, …" lines played on the speakers, and its lines arrived in sessions as the person's words, one as a typed-looking message. The echo guard covers only interccom's own speech. Workaround: `/listen off` while playing such audio.

- Checks 2.4–2.8 (local engines): most passed. 2.8 ✅: it ignores the person while it speaks. 2.7 ❌: `/interccom stop` typed during a turn ran only when the turn ended. The desktop app queues typed input, slash commands included, regardless of the command's `immediate` flag: two `/listen` commands typed mid-turn were both recorded at 16:12:42, when the turn ended. The hub itself stops playback in 0.18 s after `/stop`. Fix (d7aad31): a Stop button above the prompt while it talks. ✅ Live: it appears while speech plays and stops it at once. Then (4680d38) a bar above the prompt with the status word, Mic on/off and Stop. ✅ Live: confirmed by the person.

- Hooks type-checked for the first time (TypeScript 5.6.3, against the API types Claude Code 2.1.304 writes): two errors, both fixed. (1) `$.prompt.submit({ asUser: false })` doesn't exist: the type only allows `asUser: true`, so coordinator reports always went through the fallback and were labelled as the person's words. They're now submitted without `asUser`, framed as the plugin's message (answers 8.1). (2) The band's `h(...)` return type needed a cast. Clean afterwards.
